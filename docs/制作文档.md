## 一、产品定位

### 1.1 一句话

**屏幕上一行五线谱、一个音符，你在下面的琴键上点出它是谁。**

打开即练，不用注册、不用连网、不用买琴。每天 5 分钟，把「看谱 → 认音」变成条件反射。

### 1.2 参考对象与取舍

参考产品「口袋五线谱」（App Store 中国区 4.7 分 / 3457 个评分）验证了这条赛道的四个支点：知识文章、分级练习、错题笔记本、练习统计。

我们保留其中三个，砍掉内容生产成本最高、对「认音」这件事帮助最小的一项：

| 口袋五线谱的做法 | 我们的取舍 | 理由 |
| --- | --- | --- |
| 浅显易懂的乐理文章 | **本期不做**，移到 V1.1 | 图文内容生产周期长，且用户真正的痛点是「看见音符反应不过来」，不是「不懂乐理」 |
| 初/中/高级分级练习，按音组拆分 | **保留并细化到 6 级**，按「线音 / 间音 / 全音域 / 换谱号」拆分 | 线音与间音分练，正好对应「锚点音」教学法（见 4.1） |
| 错题笔记本，可挑选组合再练 | **保留，加自动毕业机制** | 只记不消，错题本三个月后变成垃圾场；答对 2 次自动移出才是闭环 |
| 练习量 / 正确率图形化 | **保留并补三个指标**：平均反应时间、连续打卡、Top5 错音 | 「反应时间」才是识谱能力的真实刻度，正确率会被慢速硬算刷高 |
| QQ 群 / 邮件反馈 | **不做**，用应用内「关于」页的反馈邮箱 | 首版不做社区 |

### 1.3 差异化定位

| 维度 | 市面同类（口袋五线谱 / Tenuto / Complete Music Reading Trainer） | 音符卡 |
| --- | --- | --- |
| 上手成本 | 需先读教程或选难度 | 首屏一个「开始练习」大按钮，默认直接进 L1 |
| 反馈速度 | 通用提示音 | 点错时**同时**给出正确音高试听 + 键位高亮，让耳朵和眼睛一起纠错 |
| 错题处理 | 手动挑选 | 自动沉淀 + 加权抽题 + 连续答对 2 次毕业 |
| 练习形态 | 单一题量模式 | 题量 / 60 秒限时 / 错题专项 三种 |
| 输入方式 | 只有触屏 | 触屏 + **USB MIDI 键盘**；接真键盘后反应时间才反映视奏能力 |
| 数据 | 本地或仅统计图 | 本地 SQLite，可导出 CSV（P1） |

### 1.4 成功指标

北极星指标：**周人均有效答题数**（一次练习里反应时间 ≤ 5 秒的答题记为有效）。它同时约束了「来不来」「练不练得动」「是不是瞎点」。

| 指标 | 目标值 | 观测方式 |
| --- | --- | --- |
| 首次启动到完成第 1 次练习的转化 | ≥ 60% | 埋点（本地计数，不上传） |
| 7 日留存 | ≥ 25% | 本地会话表 |
| 单次练习完成率（进 S3 到进 S4） | ≥ 85% | 会话表 total 与 answer_record 条数比对 |
| L1 平均正确率 | 首次 55–70%，3 次练习内升至 ≥ 90% | 按 level_id 聚合 |
| 平均反应时间 | 从 4 s 降至 2 s 以内 | avg_reaction_ms |

### 1.5 MVP 边界

**做**：Android 8.0（API 26）及以上机型；识谱练习（琴键答题）、**USB MIDI 键盘答题**、6 级分级、三种练习模式、错题本与毕业机制、统计页、设置页、本地持久化、深色模式；交付一个可侧载的 release APK。

**不做**：iOS 版本、账号与云同步、排行榜与社交、知识文章、听音辨音、节奏训练、升降号与调号、内购与广告、多语言。

判断标准只有一条：**去掉它，用户还能不能完成「看谱点键 → 记录 → 复盘」这个闭环。** 不能就去掉。

## 二、目标用户与使用场景

### 2.1 用户画像

| 画像 | 占比预估 | 特征 | 关键诉求 | 对产品的约束 |
| --- | --- | --- | --- | --- |
| A. 零基础成人自学者 | 55% | 20–40 岁，想学琴/学乐理，碎片时间，怕被当成小孩 | 别幼稚、别啰嗦、有进度感 | 文案克制，不用儿歌化语气；统计页要有「我能看到自己在变强」的证据 |
| B. 6–10 岁琴童及其家长 | 30% | 家长代为安装，孩子自己练；注意力 5–8 分钟 | 好玩、有即时奖励、不打击 | 大字大键、连击奖励、答错不惩罚性音效 |
| C. 乐理/艺考入门者 | 15% | 需在短时间补识谱，能忍受枯燥 | 高效、可自定范围 | 分级要能跳、错题专项要能批量刷 |

### 2.2 核心用户故事

**故事 1（画像 A，主路径）**
下班后在地铁上打开 App → 首页显示「今天还没练」→ 点「开始练习」→ 直接进入 L1、10 题、琴键模式 → 每题平均 3 秒作答 → 中途答错 2 题，键位红闪并播放正确音 → 10 题结束进结算页，看到正确率 80%、平均 3.1 秒 → 点「再来一组」或退出。
验收：从点击图标到第一题出现 ≤ 2 次点击、≤ 3 秒。

**故事 2（画像 B）**
孩子练完 10 题，准确率 90%，结算页出现「连击 7」徽章和一句「今天的 F4 一次没错」→ 孩子愿意再点「再来一组」→ 错题本里自动多了 1 个音。
验收：结算页必须有一个「值得截图给家长看」的正向结论。

**故事 3（画像 C）**
考前集中刷题 → 做题量 50 题、切到 L6 双谱表 → 结算后去错题本，勾选全部 12 个错音 → 发起「错题专项 20 题」→ 答对 2 次的音消失。
验收：错题本「全选 → 开始专项」≤ 3 次点击。

### 2.3 使用节奏假设

单次 3–8 分钟、10–20 题；每日 1–2 次。**因此所有页面都不允许出现需要滚动才能看到主操作按钮的布局**，S2 配置页尤其要短。

### 3.2 练习模块规格

**FR-P1 开始练习**
- 首页主按钮「开始练习」使用上次的配置（首次默认 L1 / 题量 10 / 琴键）。
- 点击后直接进 S3，不经过 S2。
- 首次启动在按钮下方显示一行提示「已选：L1 · 10 题 · 琴键 → 点这里改」，点击进 S2。

**FR-P2 练习会话**
- 一次会话 = 一个 `practice_session` 记录 + N 条 `answer_record`。
- 题目在会话开始时一次性生成（题量模式）或按需生成（限时模式）。
- 同会话内**不允许连续两题是同一个音**；同一音重复出现不超过 ⌈N/3⌉ 次（N = 总题数）。
- 每题记录：目标 midi、谱号、是否答对、反应时间（从谱面绘制完成到判定的毫秒数）。
- 会话中退出（返回键）→ 弹二次确认「本次练习未完成，进度将不入账」，确认后丢弃会话。**不做中途保存恢复**（首版降低复杂度，见 10.1 风险 R7）。

**FR-P3 答题判定**
- 目标音唯一：本期只练自然音，每个题目的正确答案只有一个 MIDI 编号。
- 用户点白键 = 选中该音名，八度必须正确；点黑键直接判错（本期不考升降号）。
- 判定时机为「按下」（`onTapDown`），不是抬起，减少 100–200 ms 的感知延迟。
- 答对：键位高亮 300 ms + 播放该音 + 60 ms 后叠入判定提示音 + 600 ms 后自动进下一题。
- 答错：错误键红闪 300 ms + 正确键绿框高亮 + 错音立即发声、正确音延后 60 ms 叠入（形成「错→对」的听觉对比）+ 1500 ms 后进下一题。答错不重试。
- 单题最长停留 **10 秒**，超时判错（记为答错，计入错题本），理由见 4.6。
- 结算页正确率保留整数百分比，四舍五入；题量为 0 时显示「—」而非 NaN。

**FR-P4 限时模式**
- 总时长 60 秒，倒计时显示在进度条右侧，最后 10 秒变警示色并每秒钟一次轻震动。
- 时间到立即结算，未作答的当前题不计入 total。
- 结算展示「60 秒内答对 X 题」，与题量模式共用 S4 页面但换文案。

**FR-P5 选项模式**
- 6 个选项：正确答案 + 5 个干扰项。干扰项优先取「与正确答案同一谱号、音名相邻或八度相近」的音，避免出现一眼排除的离谱选项。
- 选项文案带八度：`C4`；若设置里选 do-re-mi 则显示 `do⁴`。
- 选项按钮最小高度 56 dp，两列三行。

### 3.3 分级模块规格

**FR-L1** 六级定义、音高集合与教学目标见第四章，代码中以 `level_id` 字符串标识：`L1`…`L6`，错题专项用 `WRONG`。
**FR-L2** 全部级别默认可选，不做强制解锁。首页展示「推荐下一级」（依据：当前级别的最近 3 次会话正确率 ≥ 85% 且总题量 ≥ 30）。
**FR-L3** 每个级别卡片显示：名称、音域、该级累计题量与正确率、最近一次练习时间。
**FR-L4** 切换级别后立即生效，下次进入练习使用新级别。

### 3.4 错题本模块规格

**FR-W1 沉淀**：任何一次答错（含超时）都把**题目目标音**写入 `wrong_note`（不是用户按下的错误键）。同一 (midi, clef) 已存在则 `wrong_count + 1`、`right_streak = 0`、更新 `last_wrong_at`。
**FR-W2 毕业**：在某次练习中连续答对同一音 2 次（`right_streak ≥ 2`）→ 标记 `mastered = 1`，从列表移出，进入「已消灭」折叠区。毕业只对错题专项练习生效，避免题量模式里顺手刷掉。
**FR-W3 列表**：按谱号分组（高音谱 / 低音谱），组内按 `wrong_count` 降序；每行显示音符缩略图、音名、错误次数、错误次数用进度式条形表达。
**FR-W4 发起专项**：勾选若干（默认全选前 10 个）→「开始专项练习」→ 从选中集合按权重抽 10 或 20 题（上限 = 选中数 × 2，允许重复出题巩固）。
**FR-W5 空态**：无错题时显示「还没有错题，去练一组吧」+ 直达按钮。
**FR-W6 手动移除**：左滑可「标记已掌握」，长按可撤销毕业。

### 3.5 统计模块规格

**FR-S1 今日卡片**：今日题量、今日正确率、今日平均反应时间。0 题时显示引导文案。
**FR-S2 连续打卡**：连续有练习记录的自然日数（按设备本地时区，跨日以 00:00 为界）。
**FR-S3 趋势**：近 7 天每日题量柱状图，横轴为日期（今天在最右），纵轴自动取最大值向上取整到 10 的倍数。
**FR-S4 分级正确率**：6 个级别的正确率横向条形，未练习的级别置灰并显示「未开始」。
**FR-S5 Top5 错音**：按 `wrong_count` 降序取 5 条，显示音符图 + 音名 + 次数，点击可直达该音的专项练习（P1）。

### 3.7 输入源管理：USB MIDI 键盘

识谱训练的目标是「2 秒内说出音名」，而在屏幕上戳键其实比弹琴慢、也不真实。接上 MIDI 键盘后，练习才变成真正的「看谱 → 弹键 → 听到结论」，反应时间也才接近视奏能力。

#### 3.7.1 设备发现与连接

**FR-M1 自动连接**：插入 USB MIDI 键盘 → 系统弹出「允许访问 USB 设备」→ 允许后 App 在 3 秒内自动连接，S3 顶栏出现「🎹 设备名」徽章。

**FR-M2 设备页**：设置页「MIDI 键盘」入口 → S9。页内含：已连接设备、**自动连接开关（默认开）**、**音符显示开关（默认开）**、移调、发声策略、已发现设备列表、刷新、**按键测试框**。

**FR-M9 自动连接**：

- 连接成功后写入「我的设备」（id / 名称 / 传输方式 / 最近连接时间，存 shared_preferences，上限 20 台）。
- **身份用「传输方式 + 名称」，不能用 id**：Android 每次插拔 USB 都会给同一台琴分配**新的** `MidiDeviceInfo.id`（实测同一台 Yamaha 连续三次插拔得到 `13#port=0` → `16#port=0` → `17#port=0`）。按 id 匹配永远对不上，还会把一台琴拆成三条记录。
  - 匹配与去重统一走 `stableKey = kind::name`（均小写去空格）。
  - 连上后把记录里的 id 刷新为当前会话的新 id（仅用于展示）。
- 自动连接目标是「我的设备」里 **lastAt 最新**的那台。
- **启动即扫描**：`NoteCardApp.initState` 里就 refresh 一次，重开 App 不必先进设备页就能连回；同时建立插拔监听。
- **冷启动竞态**：Android MIDI 服务在 App 刚起来时常常先返回空设备列表，只扫一次必然连不上 —— 空列表会**重试最多 4 次（间隔 350ms）**；且只在「确实有想自动连的设备」时才重试，没琴的用户不会白等。
- **插拔触发**：订阅插件的 `onMidiSetupChanged`，去抖 400ms 后重新扫描并尝试自动连接。
- 设置是异步读的，判断前必须 `await settingsControllerProvider.future`（早先版本用 `.value` 拿到 null，自动连接从未生效过）。
- 练习页进入时调用 `ensureScanned()`：用户从不打开设备页也能连上。

**FR-M14 我的设备**：设备页新增列表，显示连接过的历史设备：

| 元素 | 说明 |
| --- | --- |
| 名称 | 单行省略 |
| 状态 | 已连接（主色圆点）/ 未连接 · 已插入 / 未连接 |
| 连接 | 在当前扫描结果里找同 id 设备并连接；找不到则提示「不在线」 |
| 信息 | 弹窗显示 设备 ID / 传输方式 / 状态 / 最近连接时间（可复制） |
| 删除 | 二次确认后从列表移除；若正连着该设备会先断开 |

删除只移除记录，不影响实际插着的键盘。列表按 stableKey 去重，同一台琴反复插拔不会堆出多条。

**FR-M10 音符显示**：开关为开时，练习页把 MIDI 当前按下的音以**空心符头**实时画在五线谱上（右偏 2.2 个 lineGap，避免与题目符头重叠），抬起即消失。

**FR-M11 按键测试框**：展示最近 40 条原始事件（未移调、未去抖），格式 `时:分:秒.毫秒 · 按下/抬起 · 音名 · 力度`（如 `20:05:07.042`），用于现场验证连接与按键时序；黑键按 `C#4` 形式显示。

**FR-M12 断开鲁棒性（两个都要做）**：

1. **主动断开**：插件的 disconnectDevice 在设备已掉线时会抛异常，必须先清本地状态、插件报错只记日志。
2. **被动掉线**：拔线/设备关机时插件会推 onConnectionStateChanged(disconnected) 与 onMidiSetupChanged，**必须监听**并回传 UI，否则界面永远显示「已连接」。两个事件都订阅，去重后发一个 disconnected(id)。

**FR-M13 自动连接的时序坑**：设备页 initState 里立刻 efresh()，而设置在 shared_preferences 里是异步读的。用 .value 取设置会拿到 null，lastMidiDeviceId 永远为空、自动连接永不生效。**必须 wait settingsControllerProvider.future** 后再判断；保存上次设备同理。已由单测覆盖（「设置加载慢 50ms 时仍能自动连上」）。

**FR-M3 热插拔**：练习中拔线 → 立即暂停并出遮罩（见 5.9），**不丢当前题**；重新插入可原地续答。

**FR-M4 多设备**：同时只启用一台。S9 可切换，切换时先断开旧设备再连新的；不提供多设备合并输入。

#### 3.7.2 事件处理规则

**FR-M5 只认 Note On**：`velocity > 0` 视为按下；`velocity == 0` 按 Note Off 处理（部分键盘的松键约定）。纯 Note Off、CC、Pitch Bend、Aftertouch 一律忽略（首版不做踏板与力度）。

**FR-M6 通道**：监听全部 1–16 通道（Omni），不让用户设通道；同一时刻只取第一个有效事件。

**FR-M7 去抖**：一次判定后 300 ms 内的后续事件只发声、不判定，防连击与部分键盘的重复 Note On。

**FR-M8 与触屏共存**：MIDI 已连接时两条输入都有效，但同一题只判第一次；判定后统一锁 300 ms。这样键盘突然没电时，用户还能用屏幕继续。

#### 3.7.3 移调（小键盘必须解决）

25 键（C4–C6）与 37 键（C3–C6）覆盖不到 L5 需要的 C2–C4，这是接真键盘后第一个会撞上的问题。

- 设置项「键盘移调」：−2…+2 个八度，默认 0，步长 1。
- 生效方式：收到音高 `raw` → `accepted = raw + 12 × transpose`，再与题目目标比对。
- 练习页在移调 ≠ 0 时于顶栏显示「移调 +1」，避免用户忘了上次设置而误判自己「越练越差」。
- 不做音域智能拦截：插件只给设备名、拿不到键数，猜错比不猜更糟。改为 S9 里的静态提示「25 键键盘请把移调设为 +1 或 +2」。

#### 3.7.4 发声策略

键盘自带音源时，App 再播一遍会双音。设置项「琴键音来源」：

| 取值 | 行为 | 适用 |
| --- | --- | --- |
| `App 播放`（默认） | 与触屏完全一致的反馈音 | 无源控制器（如 KeyStep、Launchkey 的纯 MIDI 模式） |
| `仅设备发声` | App 只判定不出声，判定提示音仍播 | 自带音箱的电钢琴 |

判定与计分不受该设置影响。

#### 3.7.5 数据与统计

`answer_record` 增加 `source` 字段（`touch` / `midi` / `choice`）。S7 本期**不展示**该维度：MIDI 与触屏的反应时间不可直接比较，混在一起算会污染正确率的解释；V1.1 再单独出「不同输入方式的平均反应时间对比」。

#### 3.7.6 验收标准

1. 插入键盘 → 3 秒内自动连接并显示徽章；拒绝授权 → 不崩溃、提示可重试。
2. 按对 / 按错 / 按黑键的判定与触屏完全一致（走同一个判定函数，不另写一套）。
3. 拔线 → 1 秒内暂停、遮罩出现；重新插上可继续答当前题。
4. 移调设为 +1 后，弹 C5 能答对题目为 C4 的题。

## 四、分级体系与题目规则

### 4.1 教学设计依据

识谱慢的根本原因不是「数不清格子」，而是**没有锚点**。教学通行做法是先背死几个定位音，其余靠相对距离推算。本项目采用四个锚点：

- 下加一线 C4（中央 C）
- 第一间 F4
- 第二线 G4
- 第三间 C5

因此分级不按「难度星级」拍脑袋，而是按**视觉定位机制**切分：先只出线音（形状相同、位置不同，逼你记线），再只出间音，最后混打并引入加线。

### 4.2 难度体系（3 档 × 16 个分组，全音域 A0–C8 共 52 音）

> **两次变更记录**：
> ① 2026-11-22 上：原设计 6 个固定级别（L1 线音 … L6 混合）→ 改为「难度 + 分组」，对齐口袋五线谱「单音练习」。
> ② 2026-11-22 下：练习范围从 **C2–C6（29 音）扩到钢琴全音域 A0–C8（52 音）**。52 是 88 键钢琴的白键总数（2+7×7+1），参考 App 的「全音区 52」就是这个数。

### 4.4 出题规则

1. 候选集 = 该级别音高集合；限时模式与题量模式规则相同。
2. 抽题：先洗牌候选集，循环取用；一轮取完再重洗。这样保证 10 题以内不重复、50 题时分布均匀。
3. 硬约束：第 n 题 ≠ 第 n−1 题；若洗牌后相邻重复，与后一位交换。
4. 错题专项：候选集来自 `wrong_note`（`mastered = 0`），按第七章权重公式加权抽样，允许重复。
5. 干扰项（选项模式）：从**同级别其他音**中取，优先相邻 staffStep（±1、±2），不足时补同音名不同八度。

### 4.5 判定与计分口径

- 正确 = 按下的 MIDI 严格等于目标 MIDI。
- 反应时间 = 从该题谱面首次绘制完成（`addPostFrameCallback`）到判定回调的毫秒差。
- 正确率 = `correct / total`，其中 `total` 包含超时题与答错题。
- 连击（combo）= 连续答对题数，答错或超时清零；每 5 连触发一次额外反馈（徽章脉冲 + 上扬音效）。
- 有效答题 = 反应时间 ≤ 5000 ms 的正确答题，仅用于成功指标统计，不展示给用户。

### 4.6 难度曲线与超时阈值

| 级别 | 目标反应时间 | 题量模式下 10 题的合理耗时 |
| --- | --- | --- |
| L1 L2 | ≤ 2 s | 40–60 s |
| L3 L4 L5 | ≤ 3 s | 60–90 s |
| L6 | ≤ 4 s | 80–120 s |

超时阈值定为 **10 秒**，依据是最慢一档目标反应时间（4 s）的 2.5 倍。低于 10 s 会让初学者在「数格子」时被打断，产生挫败；高于 15 s 则会让练习节奏拖沓、无法在一分钟内完成一组 10 题。10 s 与限时模式的单题上限取 `min(10 s, 剩余秒数)`，两处口径必须一致。

### 4.5 音名记法（可切换，默认中国科学音高记号法）

参考 App 的分组标签（`c1–b1`、`A2–B2`）用的是**中国科学音高记号法**，所以我们把它设为默认；同时保留国际记法（SPN，`C4`/`A0`）作为可选项。

| 音（国际） | 中国科学音高记号法 | 说明 |
| --- | --- | --- |
| A0 / B0 | A2 / B2 | 大字二组：大写 + 组号 2 |
| C1–B1 | C1–B1 | 大字一组：大写 + 组号 1 |
| C2–B2 | C–B | 大字组：大写，无后缀 |
| C3–B3 | c–b | 小字组：小写，无后缀 |
| C4–B4 | c1–b1 | 小字一组：**中央 C 记作 c1** |
| C5–B5 | c2–b2 | 小字二组 |
| C8 | c5 | 小字五组 |

映射规则（`NoteNaming.chinese`）：

- 八度 ≤ 2 用大写；`2` 组无后缀，`1` 组后缀 1，`0` 组后缀 2。
- 八度 ≥ 3 用小写；`3` 组无后缀，此后后缀 = 八度 − 3。

**生效范围**：分组列表的音域副标题、练习页的答案标注与 TalkBack 语义、**键盘白键上印的字**、选项模式按钮、结算页错音列表、错题本、统计 Top5。设置里「音名记法」一项切换后立即生效（默认中国记法）。

**键盘白键带组号角标**，按乐理惯例：小字组用上标（`c¹`、`c²`），大字组用下标（`C₁`、`C₂`），大字组与小字组本身不带数字（`C` / `c`）；国际记法下直接印 `C4` / `A0`。

> 注意：这与「音名显示（C-D-E / do-re-mi）」是两个独立维度——前者决定**怎么写**（c1 vs C4），后者决定**读什么名**（音名 vs 唱名）。

### 5.3 S3 答题状态机

```text
   ┌──────┐ 加载完成      ┌────────────┐ 350ms 动画结束
   │ idle │──────────────▶│ presenting │──────────────┐
   └──────┘               └────────────┘              │
                                                      ▼
   ┌──────────┐  点对键  ┌───────────┐          ┌───────────┐
   │ correct  │◀─────────│ answering │──────────▶│ timeout   │
   │ 绿+✓ 600 │          │ 计时 100ms│  10s 或剩余归零 └────┬──┘
   └────┬─────┘          └─────┬─────┘                    │
        │ 600ms                │ 点错键                     │ 900ms
        │                      ▼                            │
        │                ┌───────────┐                      │
        │                │  wrong    │ 红+✗+抖+高亮 800ms  │
        │                └─────┬─────┘                      │
        └──────────┬───────────┴────────────────────────────┘
                   ▼
            ┌────────────┐ 有余题 ┌────────────┐
            │    next    │────────▶│ presenting │
            └────────────┘         └────────────┘
                   │ 末题 → pushReplacement → S4
```

| 状态 | 进入动作 | 可交互 | 阈值 / 流转 |
|---|---|---|---|
| idle | 读配置、预载该级采样（≤120ms）、建首题 | 仅 AppBar 返回 | 就绪即 presenting；>2s 显骨架屏 |
| presenting | 谱面淡入 150ms + 符头自上 12dp 落下 200ms（easeOutCubic） | 全部锁定 200ms | 350ms 后转 answering |
| answering | 启 100ms 计时，记 touch-down 时间戳 | 键盘/选项、暂停 | 单题超时 **10s**；限时模式取 min(10s, 剩余) |
| correct | 播正确音，记 reactionMs，连击 +1 | 全锁定防连点 | 600ms → next |
| wrong | 播错误音，连击清零，正确答案绿框 600ms，错音入库 | 全锁定 | 800ms → next |
| timeout | 橙色脉冲，连击清零，记超时（不计平均反应） | 全锁定 | 900ms → next |
| next | 写库、清反馈层、判题序 | 全锁定 | 立即 presenting 或 S4 |

连击：correct +1；wrong/timeout 立即归 0；每局从 0 起，跨局不保留。达 5 的整数倍触发额外反馈（见 5.4）。结算取「本局最高连击」。

**答错是否重试——本期结论：不重试。** 答错即记录 → 正确位置绿框高亮 600ms → 800ms 后进下一题。理由：重试把反应时间拆成两段、破坏指标可比性，且使有效题量不可控。补偿：高亮 600ms 内同时叠加正确音名（若开启显示）与键盘正确键绿框，一次看全答案；强化需求交给错题本专项。

### 5.4 反馈设计

| 维度 | 正确 | 错误 | 超时 |
|---|---|---|---|
| 色 | 成功 #15803D | 错误 #D92D20 | 警告 #B45309 |
| 谱面 | 符头 1.0→1.18→1.0，250ms easeOutBack；绿环 12→32dp 淡出 300ms | 符头 ±6dp 抖动 3 次共 300ms；正确位置绿框 600ms | 谱面 2dp 橙边 150ms 淡入；符头 1.0→1.08 脉冲 2 次（400ms/次） |
| 横幅 | 「✓ 正确！+1」自下 8dp 滑入 150ms，停 600ms 淡出 150ms | 「✗ 正确答案 G4」停 800ms | 「⏱ 超时 答案 G4」停 900ms |
| 键盘 | 命中键 #D6E0F7 保持 200ms | 命中键错误色 200ms，正确键绿框 600ms | 正确键绿框 600ms |
| 触觉 | `lightImpact` | `mediumImpact` | `heavyImpact` |
| 音效 | 播按下的那个音（0.9 音量） | 只播按下的音（0.9 音量），**不再叠正确音**（2026-11-22 调整，见 6.4.1-4） | 无额外音效，靠视觉 + 震动 |

连击每 5 连追加：谱面顶部 3 个星形粒子（24dp，上浮 40dp，300ms easeOutQuart，透明度 1→0）；横幅改「COMBO ×5」并主色描边 2dp 脉冲一次 250ms；音效加琶音 C5-E5-G5（每音 60ms，共 180ms，0.5 音量）；`mediumImpact` 后 20ms 再 `lightImpact`。

### 5.5 钢琴键盘组件规范

竖屏 1 八度 = 8 白键（C D E F G A B C）+ 5 黑键（C# D# F# G# A#）。

**键宽定稿：`whiteKeyW = (W − 32) / 8`**（W 为屏宽）。之所以除以 8 而不是 7：一个八度含首尾两个 C，共 8 个白键，除以 7 会多出 46.9dp、末键被截掉一半。360→41.0dp，393→45.1dp，411→47.4dp；黑键 = 0.62×白键（25.4 / 28.0 / 29.4dp）。下限 `max(38, (W−32)/8)`，低于 38dp 说明屏宽不足 336dp，转 2 八度分页而不是继续压缩。

41dp 的白键宽低于 48dp 的无障碍建议值，靠**左右各外扩 1.5dp 的热区**补到 44dp（见下方「命中热区」），并在按下时描边 + 触觉反馈降低误触感。

| 尺寸项 | 360×800 | 393×873 / 411×891 | 大屏 ≥600dp 可用宽 |
|---|---|---|---|
| 白键宽 | 41.0dp | 45.1 / 47.4dp | `(W−48)/14`，768→51.4dp |
| 白键高 | 180dp | 194dp | 200dp |
| 黑键宽 | 25.4dp | 28.0 / 29.4dp | 31.9dp |
| 黑键高 | 112dp | 120dp | 124dp |
| 圆角 | 白 底 8dp、黑 底 6dp | 同 | 同 |
| 键间隙 | 1.5dp 描边 #E4E7EC | 同 | 同 |
| 键盘上边距 | 8dp | 8dp | 8dp |
| 八度条 | 24dp，caption 12/18 | 24dp | 24dp |
| 底部避让 | 64dp（手势条 24 + 40 余量；三键读 `viewPadding.bottom`） | 同 | 44dp |

**命中热区**：黑键本体 25.4dp <44dp，左右各外扩 7.3dp 至 40dp（高 112dp 达标）；黑键矩形内一律判黑键。白键 41×180dp 宽不足，左右外扩 1.5dp 至 44dp（间隙均摊不重叠）。所有键 `onTapDown` 即判定，≤60ms 出反馈。

**按下态**：白键 #D6E0F7（暗 #C7D2E6）、黑键 #3A4048（暗 #232830），`AnimatedContainer` 80ms easeOut；黑键另下沉 2dp。

**滑音**：**支持**。按下后横移，途经键亮起发声（同键 60ms 一次），但**只有按下瞬间所在键提交答案**，不产生第二次判题。

**八度切换**：键盘区横拖 ≥24dp 或 fling ≥400dp/s，250ms easeOutCubic 位移一屏，指示器同步，触觉 `selectionClick`。可切换范围受当前级别音域限制（如 L1 只 E4–F5，仅两页），越界时 12dp 渐隐遮罩且不响应拖动。

**大屏规则**：锁定竖屏、不做横屏；可用宽 ≥600dp（平板竖屏）切 2 八度（15 白 10 黑，按 C2/C3/…/C5 翻页），间隙 1.5dp 不压缩，lineGap 截顶 20dp，谱面改最大 640dp 居中卡片。分屏/小窗不单独适配（见 9.5 M22）。

### 5.7 无障碍

最小可点 44×44dp，视觉小于此值必须外扩热区；正文对比度 ≥4.5:1，≥20sp 粗体 ≥3:1；图标按钮必须带 `Semantics.label`。

TalkBack 语义文案（实际值）：
1. 琴键：「中央 C 白键，双击作答」→ `Semantics(label:'中央 C 白键', button:true)`。
2. 谱面：「练习音符：高音谱表第二线，音名 G4，请在键盘上找到它」。
3. 进度：「第 3 题，共 10 题，当前连击 2，本轮已用时 24 秒」。
4. 结算：「正确率 87%，8 题正确，1 题错误，1 题超时，平均反应 1.8 秒」。

色盲友好：对/错同时用**颜色 + 图标（✓/✗/⏱）+ 文字（正确/错误/超时）**三通道；不用红绿表达进度或级别高低（改用填充比例 + 数值）；符头不靠颜色承载语义。字体缩放支持 1.0–1.3×，1.3× 时卡片高度自适应，键盘高度不随字号变化。

## 六、技术方案

> 范围：单机离线、无账号无后端【假设：本期不做云同步与登录】。平台：Flutter 3.24+ / Dart 3.5，**仅 Android**，minSdk 26（Android 8.0），targetSdk 跟随发版时最新稳定版（发布前复核），只在 Android 真机/模拟器验证；**锁定竖屏**（`AndroidManifest` 声明 `portrait`），不做横屏布局，可用宽 ≥600dp 的大屏按 5.5 展开 2 个八度。基准机为骁龙 778G / 天玑 8100 级中端设备；本章数字是该机目标值，标【待验证】的需在 M2 实测。

### 6.1 技术选型总表

| 领域 | 选择 | 备选 | 为什么选它 / 放弃备选会怎样 |
|---|---|---|---|
| 状态管理 | Riverpod 2.x | Bloc 8、Provider 6 | 会话状态跨 S2→S3→S4 共享，设置变更只应重建局部。Riverpod 的 `Notifier` + `select` 按字段订阅，测试用 `ProviderContainer(overrides:)` 注入假仓库；Bloc 为 6 个状态写 120 行样板，8 页规模不划算；Provider 依赖运行期才报错，也无 `family` 的编译期约束。 |
| 路由 | go_router 14.x | auto_route、Navigator 1.0 手写 | 4 个 Tab（练习·错题本·统计·我的）用 `ShellRoute` 保持各自栈；结果页 `replace` 禁止回退；深链进错题本。手写要 300 行且易漏；auto_route 再引入 codegen，与 drift 的 build_runner 叠加拉长构建；Navigator 1.0 切 Tab 会丢状态。 |
| 本地库 | drift（SQLite） | sqflite、hive、isar | 统计要 SQL 聚合（今日量、近 7 天、打卡去重、Top5 错音），hive 要手写全表扫描；sqflite 无类型安全，手写 Map 在 3 张表、5 个聚合查询上出错概率高；isar 维护状态需核实【待验证】。drift 编译期校验 SQL、`NativeDatabase.memory()` 可做 DAO 单测，5 万行内聚合 <10ms【待验证】。 |
| 音频 | flutter_soloud | audioplayers、just_audio | 需要同时发声（琴音 + 判对提示音重叠）且点击到出声 <100ms。audioplayers 每个 `AudioPlayer` 一条流，并发要池化 6 个实例，内存与切换成本翻倍；just_audio 面向长音频/流媒体，单音触发偏重。SoLoud 是原生混音器，预载采样常驻内存，多声部混音不额外占 Dart 内存。 |
| 谱面渲染 | CustomPainter | 切图、flutter_svg、Verovio | 本期每题只画一个音 + 谱号 + 加线，切图在平板/横屏会糊且无法随 lineGap 缩放；SVG 每帧解析 DOM 级结构；Verovio 做整谱排版，引入 WASM/JS 体积 >2MB 且超出需求。Path 方案单帧约 20 条绘制指令，实测预算 <2ms。 |
| 字体 | Bravura（SIL OFL 1.1） | Noto Music、自绘谱号路径 | 自绘谱号要 20+ 段贝塞尔，难做出真谱比例；Bravura 遵循 SMuFL、OFL 允许随 App 分发，只需 U+E050/U+E062 两个码位，打包约 600–700KB【待验证】；Noto Music 字形覆盖与五线谱排版惯例不一致，谱号垂直比例需二次修正。 |
| 图表 | fl_chart | syncfusion、自绘 | 本期只有近 7 天柱状图与正确率折线。fl_chart 纯 Dart、无原生依赖，包体约 300KB；syncfusion 需商业授权（社区版有条款限制）；自绘能再省 300KB，但柱宽、坐标轴、点击提示要自己写，性价比低。若包体超标，图表是第一个可替换项。 |
| MIDI 输入 | flutter_midi_command 1.4.0 | 自写 MethodChannel、MIDI Pro | 底层就是 `android.media.midi`，插件把设备发现、USB 授权、热插拔、Typed Message 解析都封好了；自写要 400 行 + 两套权限流程。BLE 拆在独立包里，本期不引。 |
| 测试 | flutter_test + integration_test + golden | patrol、mocktail | 最大风险在谱面像素与分数计算，golden 能锁像素回归；drift 用内存库做 DAO 单测；integration_test 是官方方案，patrol 需额外原生配置。仓库用 Riverpod override 替代 mocktail，少一个依赖。 |

选型原则：8 个页面、单会话状态、本地数据 <100MB，任何引入原生插件或 codegen 的决定必须在一个里程碑内验证；验证不了的方案不进主干。

依赖方向硬规则：`presentation → application → domain ← data`，`core` 可被任意层依赖，`domain` 不依赖 Flutter 与数据层。

- `presentation` 只调 `application` 和 `domain`，禁止 import `data/`；否则换存储要改 UI，控制器也无法单测。
- `data` 实现 `domain/repos` 接口，禁止反向 import feature，否则 DB 细节泄漏到领域层。
- `domain` 不 import `package:flutter/` 与 `drift`，保证纯 Dart 可测。
- 落地检查：`tool/check_imports.dart` 扫 `lib/` 的 import，发现「presentation 引 data」「domain 引 flutter/data」「data 引 features」任一条就打印行号并让 CI 失败。规则必须可执行。

### 6.3 五线谱渲染方案

#### 6.3.1 画布尺寸契约

记页面可用宽度为 `availableWidth`（左右各 16dp padding 之后），单位 dp：

```text
lineGap      = (availableWidth / 28).clamp(10.0, 20.0)
staffWidth   = min(availableWidth, 560)
canvasHeight = 9 * lineGap
originY      = 6.5 * lineGap        // 最下谱线（treble E4 / bass G2）的 y
y(step)      = originY - step * lineGap / 2
```

- 除数取 28 而不是 40：`availableWidth` 已是扣除左右 16dp 后的宽度（360dp 屏 = 328dp）。328/28 = 11.7，符头长轴约 14.5dp，2x 屏上是 29 个物理像素，边缘清晰；若取 /40 只有 8.2、被下限抬到 12，等于在手机上恒定、失去随屏宽缩放的意义。**此公式与第五章 5.2、5.5、9.3 的三档基准值（11.7 / 12.9 / 13.5）同源，任何一侧改动必须同步另一侧。**
- 下限 10：320dp 小屏 288/28 = 10.3，再窄压到 10，五线总高 40dp 是肉眼可辨的底线。
- 上限 20：600dp 起触顶，谱高 80dp，避免把键盘挤出屏幕；`staffWidth ≤ 560`，不把谱线拉满屏。
- `canvasHeight = 9 × lineGap`：以 originY = 6.5×lineGap 为第一线，向上可容到 staffStep=12（0.5×lineGap 余量，C6 的两条上加线），向下可容到 staffStep=−4（8.5×lineGap，C2 的两条下加线），正好覆盖 C2–C6。
- 契约公式 `y = staffTop + staffStep × (lineGap/2)` 是「y 轴向上、staffTop 为基线线」的抽象坐标；Flutter 画布 y 轴向下，所以落地为减号，并令 `originY = staffTop`。若照字面用加号，音越高画得越靠下，整张谱上下颠倒。

| 设备宽（dp） | availableWidth | lineGap | 谱高 | canvasHeight | 适用 |
|---|---|---|---|---|---|
| 360 | 328 | 11.7 | 46.8 | 105.3 | 基准机 |
| 393 | 361 | 12.9 | 51.6 | 116.1 | 主流全面屏 |
| 411 | 379 | 13.5 | 54.0 | 121.5 | 主流全面屏 |
| 600 | 568 | 20.0（触顶） | 80 | 180 | 折叠/大屏 |
| 800 | 768 | 20.0（触顶） | 80 | 180 | 平板 |

#### 6.3.2 绘制顺序与 Canvas 调用

`paint(Canvas canvas, Size size)` 内严格按序执行，`Paint`/`TextPainter` 全部预建或缓存：

| 序 | 层 | 内容 | Canvas 调用 | 实现要点 |
|---|---|---|---|---|
| 1 | 五线 | 5 条水平线 | `canvas.drawLine` | `strokeWidth = max(1.0, lineGap/10)`，颜色 `onSurface` 87% 透明 |
| 2 | 谱号 | U+E050 / U+E062 | `TextPainter.paint` | 字号 `4×lineGap`，按 6.3.4 锚点定位，缓存 TextPainter |
| 3 | 加线 | 谱表外每 2 步一条 | `canvas.drawLine` | 长 `2.4×lineGap`，以符头 x 居中；先画，被符头覆盖 |
| 4 | 符头 | 旋转椭圆 | `canvas.drawPath` | 实心/空心见 6.3.3 |
| 5 | 符干 | 竖线 | `canvas.drawRect` | 宽 `max(1.2, lineGap×0.09)`，长 `3.2×lineGap` |
| 6 | 辅助线 | 音名提示、答错引导 | `canvas.drawLine`、`drawRRect` | 默认关闭；虚线用 PathMetric 切段（Canvas 无 dash） |

「辅助线」是教学辅助层（C-D-E 音名小字、答错时指向正确线位的箭头），不参与定位；它最后画，不被谱线与符头盖住。播放反馈的抖动动画在 widget 层做 `Transform`，不进 painter。

#### 6.3.3 符头 Path 与符干

```dart
Path buildNotehead(Offset center, double lineGap, {required bool hollow}) {
  final w = 1.24 * lineGap;          // 长轴 = 2 × 0.62 × lineGap（与第五章「符头半径 0.62×lineGap」同源）
  final h = w / 1.18;                // 宽高比 1.18（契约）
  final oval = Path()
    ..addOval(Rect.fromCenter(center: center, width: w, height: h));
  final rotated = oval.transform(
    (Matrix4.identity()..rotateZ(-20 * pi / 180)).storage,
  );
  if (!hollow) return rotated;       // 四分音符实心
  final inner = Path()
    ..addOval(Rect.fromCenter(
      center: center, width: w * 0.52, height: h * 0.52));
  final innerRotated = inner.transform(
    (Matrix4.identity()..rotateZ(-20 * pi / 180)).storage,
  );
  return Path.combine(PathOperation.difference, rotated, innerRotated);
}
```

- 空心符头（二分/全音符）用「外椭圆减内椭圆」的 even-odd 填充，壁厚约 `0.24×h`，比 `stroke` 更接近铜版谱；实心符头直接 fill。
- 符干方向：`staffStep < 4`（中线以下）符干朝上，贴符头右侧；`staffStep ≥ 4` 朝下，贴左侧。长度 `3.2×lineGap`，宽 `max(1.2, lineGap×0.09)`；符干不参与 hit test。
- 符头 x 固定在 `staffWidth × 0.62`，不随音高移动：位置固定才能练「读位置」，来回跳会让用户追着音符看。
- 符头 y 由 `y(step)` 计算，加线与符头中心共用同一 y，避免 1px 错位。

#### 6.3.4 谱号：Bravura 字体与基线对齐

- Bravura 只在 pubspec 注册 `fontFamily: 'Bravura'`，随包附 OFL.txt；设置页「关于」写字体名与 OFL 链接。
- 字号 `fontSize = 4 × lineGap`：SMuFL 规定 1 em = 4 个间，这样谱号高度与谱表比例稳定，不随设备漂移。
- **锚点不是第 1 线**：高音谱号的卷曲中心在 G4（第 2 线，staffStep=2），低音谱号的两点在 F3（第 4 线，staffStep=6）。若把两个谱号都按第 1 线对齐，treble 会整体上移约 1.5 个间，用户按卷曲找 G 线就会错位，所以本方案按各自基准线定位。
- 基线对齐：`TextPainter.layout()` 后取 `computeDistanceToActualBaseline(TextBaseline.alphabetic)` 作为基线到文本框顶的距离，再用一次性 golden 标定常数把「谱号墨迹锚点」落到目标线：

```dart
final fs = 4 * lineGap;
final tp = clefPainter(clef, fs);                 // 缓存，不每帧 layout
final anchorY = clef == Clef.treble
    ? originY - 1 * lineGap                      // G4 线
    : originY - 3 * lineGap;                     // F3 线
final yTop = anchorY - kAnchorFromTop[clef]! * fs;
tp.paint(canvas, Offset(0.35 * lineGap, yTop));
```

`kAnchorFromTop` 是「视觉锚点到文本框顶」的字号比例，初值 treble≈0.62、bass≈0.74【假设·待 golden 标定】：400pt 字号渲染单字到 512×512 白底，扫 alpha>8 的墨迹包围盒，人工确认卷曲/两点像素行后写死常量并锁 golden。OTF 不含排版元数据，运行时不解析 bbox，标定一次即可。

#### 6.3.5 加线规则与边界

判定：`staffStep < 0` 或 `staffStep > 8` 才画，且只在偶数步（线位）画。上方从 10 开始、下方从 −2 开始，向远离谱表方向每 2 步一条：

```text
上方：s = 10, 12, 14 … 直到 s ≤ staffStep
下方：s = −2, −4, −6 … 直到 s ≥ staffStep
C4 在 treble：step = −2 → 画 −2，共 1 条
C6 在 treble：step = 12 → 画 10、12，共 2 条
G5 在 treble：step = 9 → 不画（谱表外相邻间，属正常音区）
C2 在 bass：step = −4 → 画 −2、−4，共 2 条
C4 在 bass：step = 10 → 画 10，共 1 条
```

边界要区分「间」与「线」：step=9/−1 不画，画了会把间内音伪装成线音；step=11 只画 10，因为 11 不是线位。

#### 6.3.6 重绘优化

- 拆两个 painter 并各自套 `RepaintBoundary`：`StaffPainter`（五线 + 谱号，仅尺寸/主题变化时重建）与 `NotePainter`（加线、符头、符干、辅助层，逐题重绘）。
- 谱线用 `Picture` 缓存：`PictureRecorder` 录一次五线与谱号，之后每帧 `canvas.drawPicture`，省掉 5 次 drawLine 与一次文字排版。
- `shouldRepaint` 只比较影响像素的字段，不做对象深比较：

```dart
@override
bool shouldRepaint(covariant NotePainter old) =>
    old.midi != midi ||
    old.clef != clef ||
    old.lineGap != lineGap ||
    old.showNoteName != showNoteName ||
    old.accent != accent;
```

- `paint()` 内禁止：`TextPainter.layout()`、新建 `Paint`、读 Provider/shared_preferences、`await`。
- 页面层用 `ref.watch(controller.select((s) => s.currentMidi))`，答题结果动画走 `AnimationController` + `Transform.translate`，不动 painter。
- 预算：单帧 painter <2ms、UI 线程 <8ms、掉帧率 <1%；用 `SchedulerBinding.instance.addTimingsCallback` 采集 `FrameTiming`，M3 起纳入回归。

### 6.4 音频方案（Android 专项）

#### 6.4.1 素材与包体

- 源：Salamander Grand Piano V3，CC BY 3.0（Tone.js CDN 分发版）。
- **实测落地（与原计划的差异）**：Tone.js 那套只提供 **每 3 个半音一个采样**（C/Ds/Fs/A），C2–C6 共 **17 个文件 / 1.19 MB**，不是原先设想的 49 个全半音采样。其余音高用 `setRelativePlaySpeed` 变速补足：采样网格密，最大偏移 1.5 个半音，音色失真在识谱练习里可接受，也省了 2/3 素材体积与 ffmpeg 转码环节（原计划要装 ffmpeg 转 ogg，实测直接可用 mp3）。
- 采样点（MIDI）：21 24 27 30 33 / 36 39 42 45 / 48 51 54 57 / 60 63 66 69 / 72 75 78 81 / 84 87 90 93 / 96 99 102 105 108，共 **30 个 / 1.92 MB**（A0–C8，每 3 个半音一个）；播放时按 `2^((midi - sample)/12)` 变速，clamp 0.5–2.0。
- 引擎初始化：`SoLoud.init(sampleRate: 44100, bufferSize: 2048)`，进练习页时预热（0 音量播 C4 一次建轨），实测 AAudio 开流并输出 34398 帧。
- **依赖锁 `flutter_soloud: ^4.0.0`（不能用 5.x）**：5.x 改成 Dart build hook，`flutter test` 时要在宿主机（Windows）编 C 代码，本机没装 MSVC 会直接报 `error code: 126` / `No compiler configured on host 'windows_x64'`，整个测试套件跑不起来。4.x 的原生构建走 Android CMake，宿主机不需要编译器；代价是 API 少了 `lowLatency` 参数（默认就是低延迟路径）。
- 引擎必须**惰性获取**（`SoLoud.instance` 放到 `init()` 里再取）：写在字段初始化里的话，测试环境下取实例就抛错，Provider 直接进 error state，整棵页面树渲染不出来。
- ~~答错时 60ms 后补一遍正确答案的音~~：**2026-11-22 实机试听后取消**——一次点击会听到两个音，用户第一反应是「点一下响两次」。改为**每次点击只响一个音**，正确答案只靠符头变红、正确键高亮与横幅提示。
- 音效开关：设置页与练习页顶栏（🔊/🔇）共用同一个 `soundEnabled`，默认开。实测 A/B：开 → 点键触发 AAudio 开流；关 → 0 次开流。
- 转码（48 kHz 单声道，与 Android 输出对齐）：`ffmpeg -i in.wav -ac 1 -ar 48000 -c:a libvorbis -b:a 96k piano_036.ogg`，文件名按 MIDI 三位补零。
- 不裁剪：裁到 3s 能省一半体积，但衰减被切断会显得音「假」，本期保留完整尾音。
- 体积：49 × 平均 6.0s × 12KB/s ≈ 3.5MB，3 个 UI 提示音约 40KB；素材总计 ≈3.54MB。
- UI 提示音（correct / timeout / combo）**预渲染为 ogg，不在运行时做波形合成**：第五章 5.4 给的频率、时长、音量是「制作规格」，交付物是 3 个固定采样。理由：SoLoud 的实时波形 API 跨版本差异大【待验证】，且采样才能进 golden 化的音频回归。答错时**不播额外提示音**，只播「按错的音」+ 60ms 后叠入的正确音，避免三音叠加发糊。

#### 6.4.2 播放链路与延迟

flutter_soloud 底层是 miniaudio：Android 上优先 AAudio（API 26+，低延迟共享模式），不可用或初始化失败时退化到 OpenSL ES。AAudio 缓冲更浅、路由更直接；OpenSL ES 的 buffer queue 更深，触摸到出声的 P95 目标从 80ms 放宽到 120ms【待验证】。启动时探测一次后端并缓存，不在播放时重试。

- 输出采样率对齐 48 kHz：免掉 44.1→48 重采样，也避免部分机型在 44.1 下走更深缓冲。
- 不在每帧/每次点击新建播放实例：`AudioService` 单例，`init` 只在启动执行一次；`AudioSource` 预加载后按 MIDI 缓存复用。
- 预加载到内存池：按当前音域 ±1 个八度加载，LRU 上限 24 个源（解码内存 ≈24×6s×48kHz×2B≈13.8MB），低端机上限 12（≈6.9MB）。
- 启动预热：init 完成后以音量 0 播放 C4 50ms 再停，强制建轨与首包解码，避免第一次点琴键 150–400ms 的冷启动延迟。
- `AudioManager` 保持 `MODE_NORMAL`，禁止 `MODE_IN_COMMUNICATION`：后者会切通话路由、降采样并启用回声消除，琴音发闷。练习页用 `AUDIOFOCUS_GAIN_TRANSIENT` 拿焦点，离开 S3 即放弃。
- 采样解码不在 UI 线程：`loadAsset` 放启动/进页异步任务，点击回调只 `play` 已缓存源；未命中时静音跳过并后台补载，绝不 `await` 解码。

#### 6.4.3 生命周期与并发

| 时机 | 动作 | 失败处理 |
|---|---|---|
| App 启动后首帧 | 异步 `init()`，3s 超时 | `available=false`，不阻塞 UI |
| 进入 S2/S3 | 预载本级音域 ±1 八度 | 单条失败跳过，继续出题 |
| 发题 | 确认该音源已在缓存（命中 <0.1ms） | 未命中则静音，后台补载 |
| 点琴键/答对 | `play(midi)`，不等待播放结束 | try/catch，连续 3 次失败关音效 |
| 离开 S3 5s | 释放音域外源，缓存回落到上限内 | — |
| 退后台 | `stopAll()`，释放音频焦点 | — |
| App 退出 | `deinit()` | — |

并发上限 **8 个声部**（与第五章 5.4「共用 8 声道池」、U16、M08 同口径）：一次快速连点最多叠 8 个音，超过时主动 `stop` 最早的非答案音句柄（自建 FIFO），不做无上限叠加，否则低端机会出现爆音与掉帧。

```dart
class AudioService {
  final Map<int, AudioSource> _cache = {};
  bool available = false;
  bool soundOn = true;

  Future<void> init() async {
    try {
      await SoLoud.instance.init().timeout(const Duration(seconds: 3));
      available = true;
      await _warmUp();                       // 0 音量播 C4，建轨
    } catch (e, st) {
      available = false;
      log.w('audio init failed', e, st);     // 只降级，不抛出
    }
  }

  Future<void> preload(Iterable<int> midis) async {
    if (!available) return;
    for (final m in midis) {
      if (_cache.containsKey(m)) continue;
      if (_cache.length >= 24) _evictLru();
      _cache[m] = await SoLoud.instance
          .loadAsset('assets/audio/piano_${m.toString().padLeft(3, '0')}.ogg');
    }
  }

  void play(int midi) {
    if (!available || !soundOn) return;
    final src = _cache[midi];
    if (src == null) { unawaited(preload([midi])); return; }
    unawaited(SoLoud.instance.play(src, volume: 0.9));
  }
}
```

函数名以锁定版本的 flutter_soloud 公开 API 为准【待验证】；`play` 返回句柄即返回，不等播完，避免阻塞点击链路。

#### 6.4.4 降级与系统占用

- 初始化失败/超时：`available=false`，音效开关置灰并提示「音频不可用」，练习照常；只弹一次 SnackBar。
- 被其他 App 占用（通话、导航）：焦点请求失败就不抢，音效静音，答题零影响；恢复后手动重开或下次进页重试。
- 用户关音效：不 init、不加载、立即 `disposeSource` 释放内存；再打开时重新 init 并预载当前音域。
- 所有音频调用包 try/catch，异常 3 次即全局关音效。

#### 6.5.4 事务边界（结论：会话结束单事务批量写）

| 方案 | 写入次数 | 估算耗时 | 风险 |
|---|---|---|---|
| A：每题一个事务 | 1 session + 50 answer + ≤50 upsert，即 ≤101 条写入语句（按 101 次 commit 计） | 中端机每次 commit 2–5ms，合计 200–500ms，分散在答题过程中 | 每次 commit 有卡顿风险，且写放大 |
| B：会话结束单事务 | 1 次事务，51 条 INSERT + ≤50 条 upsert | 8–20ms，一次性 | 进程被杀丢 1 场（≤50 题） |

选 B：答题期间答案只进内存 `List<AnswerResult>`，结算时一个事务写完。50 次 WAL commit 的抖动会落在答题节奏上；B 只在结算页写一次，用户预期就是「等一下出成绩」；崩溃最多丢一场，由 30s 快照兜底（见 6.7）。

```dart
Future<int> finishSession(SessionDraft d) => db.transaction(() async {
  final id = await into(db.practiceSessions).insert(
    PracticeSessionsCompanion.insert(
      mode: d.mode.name, levelId: d.levelId,
      startedAt: d.startedAt, endedAt: d.endedAt,
      total: d.answers.length,
      correct: d.answers.where((a) => a.isCorrect).length,
      avgReactionMs: _avgReaction(d.answers),
    ),
  );
  await batch((b) {
    for (final a in d.answers) {
      b.insert(db.answerRecords, AnswerRecordsCompanion.insert(
        sessionId: id, midi: a.midi, clef: a.clef.name,
        isCorrect: a.isCorrect ? 1 : 0,
        reactionMs: a.reactionMs, answeredAt: a.answeredAt,
      ));
    }
    for (final w in d.wrongDeltas) {
      b.insert(db.wrongNotes, w.toCompanion(),
          onConflict: DoUpdate((old) => w.toCompanion()));
    }
  });
  return id;
});
```

`wrongDeltas` 在内存里按 `(midi, clef)` 聚合，一场最多 58 行，事务内不查库。

### 6.7 异常与降级

| 场景 | 检测 | 降级动作 | 用户感知 |
|---|---|---|---|
| 数据库损坏 | open 抛 SQLITE_CORRUPT/NOTADB 或迁移异常 | 原文件改名 `notecard.corrupt-<ts>.db`，重建空库，保留 1 份；prefs 设置不受影响 | 提示「记录损坏，已重置」，可继续 |
| 迁移失败 | `onUpgrade` 抛异常 | 回滚，保留旧库，进只读降级页：可练习不写记录；上报日志 | 提示「升级失败，本次不保存」 |
| 音频初始化失败/被占用 | 3s 超时、抛异常或焦点请求失败 | 关闭音效，开关置灰，答题不变 | 一次 SnackBar，不阻塞 |
| 字体缺失 | 谱号 TextPainter 宽度为 0 或异常 | 用预置简化谱号 Path 兜底；CI 的 golden 会先拦住 | 谱号略粗糙，仍可答题 |
| 时钟回拨 | `endedAt < startedAt`、`reactionMs < 0`、日期倒退 | 时长用单调 `Stopwatch`；墙钟只做日期分桶；负值 clamp 为 0；`lastWrongAt` 回拨置 now | 无感 |
| 进程被杀 | 启动读到未完成快照 | `paused` 时与每 30s 写 prefs 快照（JSON ≤2KB）；<24h 提示继续，否则丢弃 | 最多丢 30s |
| 存储写满 | 事务抛 SQLITE_FULL | 不写库，结果页仍展示成绩；提示清理空间 | 成绩可见但未保存 |

时钟细则：反应时间、60s 倒计时、动画时长都用单调 `Stopwatch`；`started_at`/`answered_at` 用墙钟毫秒，仅用于今日/近 7 天/打卡。用户改时间或 NTP 回拨时统计最多差一天，不能崩、不能出现负值。

### 6.8 为什么 Android 单平台仍选 Flutter 而不是原生 Kotlin

1. **一套代码两种资产**：本期只发 Android，但 UI、状态机、算法、drift 数据层都平台无关，日后扩 iOS 直接复用。原生 Kotlin 要把 Compose、Room、ViewModel 再写一遍，复用率为 0。
2. **画谱面更省事**：`CustomPainter` 的 Canvas/Path/TextPainter 与 Android 同源，Flutter 还有 hot reload 与 golden 锁像素，谱号/符头微调秒级看结果；原生要搭 Paparazzi/Robolectric 截图链。
3. **迭代更快**：单语言 Dart + Riverpod + drift codegen，7 页 + 2 个里程碑可完成；Kotlin + Compose + Room + Navigation 约多 30% 样板。

代价：APK 比同类原生大约 **+8MB**（已计入 6.6 的 15.5–18.9MB，仍低于 20MB 红线）；首帧启动多 200–400ms【待验证】。结论：接受代价换速度与跨端资产；若包体/启动成为硬指标，优先把练习页改原生、Flutter 留壳，而不是现在放弃跨端。

#### 6.9.1 选型与依赖

| 项 | 结论 |
| --- | --- |
| 插件 | `flutter_midi_command: ^1.4.0`（BSD-3-Clause），底层就是 `android.media.midi`（API 23+，我们 minSdk 26 满足） |
| 为什么不自己写 Pigeon/MethodChannel | 系统 MIDI 的设备发现、USB 授权回调、热插拔、多端口合并、Typed Message 解析加起来约 400 行，且要处理两套权限流程；插件已提供 `onMidiDataReceived`（已解析成 `NoteOnMessage` 等类型）、`onMidiSetupChanged`、`devices` 快照与逐设备连接状态流 |
| 为什么本期不上蓝牙 | BLE 是独立包 `flutter_midi_command_ble`，一引入就会合并 `BLUETOOTH_SCAN` / `BLUETOOTH_CONNECT` 运行时权限，和「零危险权限」目标冲突；且插件有已知 bug：部分 Android 机型连接/断开后再扫描会扫不到任何设备，必须重启进程。放到 V1.1 |
| 备选 | MIDI Pro（偏输出）、music_kit（已停更）、自研通道——均不选 |
| 包体影响 | 插件 + native bridge 约 200–300 KB【待验证】 |

#### 6.9.2 清单与权限

```xml
<uses-feature android:name="android.hardware.usb.host" android:required="false"/>
<uses-feature android:name="android.software.midi" android:required="false"/>
```

- 两个 feature **必须** `required="false"`，否则没有 MIDI 能力的机型会在商店被直接过滤掉。
- USB 访问授权由系统弹窗（`UsbManager` 权限）授予，**不需要在 manifest 声明任何权限**——这是 USB 相对 BLE 的最大优势，也是本期选 USB 做 P0 的核心理由。
- 不声明任何 `BLUETOOTH_*`、不声明 `RECORD_AUDIO`。
- ⚠️ **插件的 manifest 会盖掉你的 `false`**（M−1 实测踩到）：`flutter_midi_command` 自己声明了 `android.software.midi` 且 `required="true"`，manifest merge 取**更严格**的一方，构建出来的 APK 就变成「MIDI 必需」，商店会把没有 MIDI 声明的机型过滤掉。必须写 `tools:node="replace"` 强覆盖，并在构建后用 `aapt2 dump badging` 确认输出是 `uses-feature-not-required`：

```xml
<manifest xmlns:android="http://schemas.android.com/apk/res/android"
    xmlns:tools="http://schemas.android.com/tools">
    <uses-feature android:name="android.hardware.usb.host" android:required="false"/>
    <uses-feature android:name="android.software.midi" android:required="false" tools:node="replace"/>
```

- 插件还会注册一个 `VirtualDeviceService`（`BIND_MIDI_DEVICE_SERVICE`，系统级签名权限）。本期不做虚拟 MIDI 设备，但保留它也不影响；若后续要收窄面，可用 `tools:node="remove"` 删掉。

#### 6.9.3 初始化与生命周期

| 时机 | 动作 | 失败处理 |
| --- | --- | --- |
| App 启动 | **不初始化** MIDI（省一次 Binder 查询与 10–30 ms） | — |
| 首次进 S9 或检测到 USB 设备挂载 | 懒初始化 `MidiCommand`，拉一次 `devices` 快照 | 3 s 超时 → S9 显示「MIDI 不可用」 |
| 插入设备 | 系统弹授权 → `connectToDevice`（默认 30 s 就绪超时） | `MidiConnectionException` → 提示重试，不进练习 |
| 练习中 | 订阅 `onMidiDataReceived` | 流异常 → 主动断开、退回触屏 |
| 拔线 | `onMidiSetupChanged(deviceDisappeared)` → 暂停会话（见 5.9） | 恢复靠重插或用户点「用触屏」 |
| 退出 App | `dispose()`，只调一次 | — |

`MidiCommand` 必须是**进程级单例**，不能随页面创建销毁：插件的连接状态是全局的，路由级实例会导致监听重复与连接残留。

#### 6.9.4 输入抽象（关键设计）

三种输入归一到同一个事件类型，`PracticeController` 完全不感知来源：

```dart
enum InputSource { touch, midi, choice }

class AnswerInput {
  final int midi;        // 已应用移调，保证与题目目标同一坐标
  final InputSource source;
  final int atMs;        // 单调时钟
}

abstract interface class InputAdapter {
  Stream<AnswerInput> get events;   // 一次有效按键恰好一条
  Future<void> start();
  Future<void> stop();
}
```

- `TouchKeyboardAdapter` / `MidiAdapter` / `ChoiceAdapter` 三个实现。
- 控制器只做两件事：`if (now - lastJudgedAt < 300) return;` → `judge(input.midi)`。
- 收益：单元测试直接往 `events` 里推 `AnswerInput`，不需要真机、不需要 Flutter binding、不需要真实音频设备。
- 判定函数只有一份：MIDI 与触屏共用 `judge()`，这是 FR 里「判定完全一致」的落地方式。

#### 6.9.5 延迟预算

| 环节 | 预算 |
| --- | --- |
| USB MIDI 传输 | 1–3 ms |
| 平台通道 → Dart | 1–2 ms |
| 判定 + 状态更新 | < 1 ms |
| 音频起播（已预热） | 3–8 ms |
| **合计：按键 → 出声** | **≤ 16 ms（一帧）** |

对比触屏的 `onTapDown` + 事件分发约 30–60 ms，MIDI 才是「练反应速度」的正确输入方式。这也暴露一个设计取舍：4.6 定的 10 s 超时对 MIDI 用户过宽，但**不做按输入源区分的阈值**——阈值一旦分裂，正确率与反应时间的口径就不可比了（见 11.2）。

#### 6.9.6 已知坑与对策

| 坑 | 现象 | 对策 |
| --- | --- | --- |
| OTG 供电不足 | 键盘亮一下就掉 | S9 文案提示「请换带供电的 OTG HUB」；不自动重连死循环 |
| 设备名为空或乱码 | 列表出现空行 | 回退显示 `MIDI 设备 (pid:vid)` |
| 部分键盘发重复 Note On | 一次按键判两次 | 300 ms 去抖（FR-M7） |
| 键盘通道不是 1 | 收不到事件 | 监听全部 1–16 通道（FR-M6） |
| 拔出后名单残留 | 设备仍在列表 | 只以 `onMidiSetupChanged` 刷新，不本地缓存 |
| 无 USB Host 能力的机型 | `devices` 恒为空 | S9 降级文案，不进连接流程 |
| 键盘与 App 双音 | 自带音源再叠 App 采样 | 「仅设备发声」开关（3.7.4） |

#### 6.9.7 测试策略

## 七、数据结构与核心算法

### 7.1 领域模型

```dart
enum Clef { treble, bass }

extension ClefX on Clef {
  int get baseDIndex => this == Clef.treble ? 30 : 18;   // E4 / G2
}

enum Letter { C, D, E, F, G, A, B }                      // index 即 letterIndex

class Pitch {
  final int midi;
  const Pitch._(this.midi);

  factory Pitch.fromMidi(int midi) {
    assert(midi >= 24 && midi <= 96, 'MIDI out of app range: $midi');
    assert(_naturalPcs.contains(midi % 12), 'only natural notes: $midi');
    return Pitch._(midi);
  }

  int get octave => midi ~/ 12 - 1;
  int get letterIndex => _pcToLetter[midi % 12]!;
  Letter get letter => Letter.values[letterIndex];
  int get dIndex => octave * 7 + letterIndex;
  String get name => '${letter.name}$octave';            // C4 / A4

  int staffStep(Clef clef) => dIndex - clef.baseDIndex;

  double staffY(Clef clef, double originY, double lineGap) =>
      originY - staffStep(clef) * lineGap / 2;
}

enum PracticeMode { count, timed, wrong }

class NoteQuestion {
  final int seq;
  final Pitch pitch;
  final Clef clef;
  final String levelId;
  final List<Pitch> choices;        // 选项模式 6 个，琴键模式为空
  final int presentedAtMs;          // 单调时钟，仅用于算反应时间
}

class PracticeSession {
  final int? id;
  final PracticeMode mode;
  final String levelId;
  final DateTime startedAt;
  final DateTime endedAt;
  final int total;
  final int correct;
  final int avgReactionMs;
  double get accuracy => total == 0 ? 0 : correct / total;
}

enum InputSource { touch, midi, choice }

class AnswerResult {
  final int midi;
  final Clef clef;
  final InputSource source;         // 写入 answer_record.source
  final bool isCorrect;
  final int reactionMs;
  final DateTime answeredAt;
}

class WrongNoteEntry {
  final int midi;
  final Clef clef;
  final int wrongCount;
  final int rightStreak;
  final DateTime lastWrongAt;
  final bool mastered;
}
```

### 7.2 算法 1：MIDI ↔ 音名 ↔ dIndex ↔ staffStep

| 转换 | 公式 | 示例 |
|---|---|---|
| MIDI → 音高类 | `pc = midi % 12` | 60→0 |
| 音高类 → letterIndex | `{0:0, 2:1, 4:2, 5:3, 7:4, 9:5, 11:6}` | 0→C(0) |
| MIDI → 八度 | `octave = midi ~/ 12 - 1` | 60→4 |
| MIDI → dIndex | `octave*7 + letterIndex` | 60→28 |
| dIndex → MIDI | `(dIndex ~/ 7 + 1)*12 + semitone[dIndex % 7]` | 28→60 |
| dIndex → staffStep | `dIndex - (treble ? 30 : 18)` | 28→treble −2 / bass 10 |
| staffStep → y | `originY - step*lineGap/2` | −2→originY+lineGap |
| MIDI → 音名 | `letter.name + octave` | 69→A4 |

```dart
const _semitone = [0, 2, 4, 5, 7, 9, 11];
const _pcToLetter = {0: 0, 2: 1, 4: 2, 5: 3, 7: 4, 9: 5, 11: 6};
const _naturalPcs = {0, 2, 4, 5, 7, 9, 11};

int midiToDIndex(int midi) {
  assert(_naturalPcs.contains(midi % 12), 'black key: $midi');
  return (midi ~/ 12 - 1) * 7 + _pcToLetter[midi % 12]!;
}

int dIndexToMidi(int d) {
  assert(d >= 5 && d <= 56, 'this build only A0–C8: $d');
  return (d ~/ 7 + 1) * 12 + _semitone[d % 7];
}

int staffStepOf(int midi, Clef clef) {
  final step = midiToDIndex(midi) - clef.baseDIndex;
  assert(step >= -13 && step <= 30, 'unexpected staffStep $step');
  return step;
}
```

自测：A0–C8 的 **52 个**自然音跑双向恒等；61（黑键）应抛 ArgumentError；C4 的 dIndex=28 同时验证 treble −2、bass 10；A0 的 staffStep = −13、C8 = +30（谱面要能画 6 条下加线 / 11 条上加线，lineGap 需按高度自适应）。

### 7.3 算法 2：分级题库生成

| levelId | 谱号 | 出题候选（MIDI） | 音数 | 加线范围 |
|---|---|---|---|---|
| L1 | treble | 64, 67, 71, 74, 77 | 5 | 无 |
| L2 | treble | 65, 69, 72, 76 | 4 | 无 |
| L3 | treble | C4–C6 自然音 | 15 | 下 1、上 2 |
| L4 | bass | 43, 47, 50, 53, 57 | 5 | 无 |
| L5 | bass | C2–C4 自然音 | 15 | 下 2、上 1 |
| L6 | 双谱表 | C2–C6 自然音 | 29 | 所有 |
| 错题 | 按记录 | wrong_note 中 mastered=0 | ≤58 | 按音域 |

注意 L2 只有 4 个音，凑不出 6 选 1：选项池要与出题池分离。L1+L2 合并 9 个音作为前两级的选项池；L4 的 5 个音全部包含在 L5 的 15 个音内，后两级直接用 L5 全音域做选项池；L3/L6 用本级全音域，错题用全部 29 个自然音。

```dart
class QuestionGenerator {
  final Random _rng;
  final List<int> _pool;          // 出题池
  final List<int> _optionPool;    // 选项池（≥6）
  final Clef Function(int midi) _clefOf;
  int? _lastMidi;
  int _seq = 0;

  QuestionGenerator({
    required List<int> pool,
    required List<int> optionPool,
    required Clef Function(int) clefOf,
    int? seed,
  })  : _pool = pool,
        _optionPool = optionPool,
        _clefOf = clefOf,
        _rng = Random(seed);

  NoteQuestion next() {
    assert(_pool.isNotEmpty, 'empty pool');
    var midi = _pool[_rng.nextInt(_pool.length)];
    for (var i = 0; i < 20 && midi == _lastMidi; i++) {
      midi = _pool[_rng.nextInt(_pool.length)];
    }
    if (midi == _lastMidi) {                       // 确定性兜底
      midi = _pool[(_pool.indexOf(_lastMidi!) + 1) % _pool.length];
    }
    _lastMidi = midi;
    final pitch = Pitch.fromMidi(midi);
    return NoteQuestion(
      seq: _seq++,
      pitch: pitch,
      clef: _clefOf(midi),
      levelId: '',
      choices: _buildChoices(pitch),
      presentedAtMs: _monotonicMs(),
    );
  }

  List<Pitch> _buildChoices(Pitch answer) {
    final others = _optionPool.where((m) => m != answer.midi).toList()
      ..shuffle(_rng);
    // 干扰项优先取 ±7 半音内的音，更像；其余随机
    final near = others.where((m) => (m - answer.midi).abs() <= 7).toList();
    final picked = <int>{
      answer.midi,
      ...(near.isNotEmpty ? near.take(3) : others.take(3)),
      ...others.take(6),
    }.take(6).toList()
      ..shuffle(_rng);
    return picked.map(Pitch.fromMidi).toList();
  }
}
```

- 同会话不连续重复：最多重抽 20 次，仍相同则取池中下一个，保证 O(1) 收尾不死循环。
- 题量模式出 10/20/50 题后停；错题专项 10/20 题；限时模式不设上限，答到 60s 为止。
- 选项全部带八度标注（`C4`、`A4`），选中后比 `answer.midi`，不能只比音名。
- 测试：`Random(42)` 生成 1000 题，断言相邻 midi 不同、全在池内、选项无重复且含答案、L2 选项数 ≥6。

### 7.4 算法 3：错题调度（加权随机 + 简化间隔重复）

权重公式：

```text
urgency = 1 + 1.5 × min(wrong_count, 6)          // 1.0 ~ 10.0
recovery = 1 / (1 + 0.7 × right_streak)          // 1.0 / 0.59 / 0.42
overdue = (now - last_wrong_at ≥ interval(right_streak)) ? 2.0 : 1.0
weight = urgency × recovery × overdue

interval(0) = 0h   // 刚错，立刻重练
interval(1) = 24h
interval(≥2) = 不参与（已掌握）
```

例：错 3 次、连对 0、2 天前错 → 11.0；错 1 次、连对 1、1 小时前 → 1.47，前者抽中概率约为后者 7.5 倍。

抽取 n 题用轮盘赌不放回：累加权重取随机点，选中后从池中移除，直到凑满 10/20 题；池不够时允许第二轮重复（同会话可重复，但相邻不重复）。

字段更新规则：

| 事件 | wrong_count | right_streak | last_wrong_at | mastered |
|---|---|---|---|---|
| 答错 | +1 | 0 | now | 0 |
| 答对且 streak 变 1 | 不变 | 1 | 不变 | 0 |
| 答对且 streak 变 2 | 不变 | 2 | 不变 | 1（移出候选池） |
| 已掌握后再答错 | +1 | 0 | now | 0（复活） |

- 答对不刷新 `last_wrong_at`，逾期仍以最后一次错为准；`mastered=1` 行保留供统计。
- 「连续答对 2 次」不要求跨会话/跨天，同会话两题都对也算，避免当天清不掉错题。
- 任何模式答错都 upsert 进错题本，错题专项也更新，形成闭环。
- 错题池为空（全部 mastered）：回退最近一次练习的 level，没有则 L3，并提示「错题已清空，已切到 L3 巩固」；专项请求 20 题但池中仅 6 个音时，第二轮重复并提示。

### 7.5 算法 4：统计聚合

今日（本地日界，毫秒）：

```sql
SELECT COUNT(*) AS total,
       COALESCE(SUM(is_correct), 0) AS correct,
       COALESCE(CAST(AVG(reaction_ms) AS INTEGER), 0) AS avg_ms
FROM answer_record
WHERE answered_at >= :dayStart AND answered_at < :dayEnd;
```

Top5 错音（按音高合并谱号，符合用户「这个音总认错」的感知）：

```sql
SELECT midi, SUM(wrong_count) AS wc, MAX(last_wrong_at) AS last
FROM wrong_note
WHERE mastered = 0
GROUP BY midi
ORDER BY wc DESC, last DESC
LIMIT 5;
```

近 7 天柱状（返回已有日期，缺失日补 0）：

```sql
SELECT CAST((answered_at + :tzOffsetMs) / 86400000 AS INTEGER) AS day,
       COUNT(*) AS c, COALESCE(SUM(is_correct), 0) AS ok
FROM answer_record
WHERE answered_at >= :fromMs
GROUP BY day ORDER BY day;
```

连续打卡（Dart，避免 SQLite `localtime` 在部分 ROM 上的时区差异）：

```dart
Future<int> streakDays(DateTime now) async {
  final rows = await db.customSelect(
    'SELECT DISTINCT CAST((started_at + ?) / 86400000 AS INTEGER) AS day '
    'FROM practice_session ORDER BY day DESC',
    variables: [Variable.withInt(now.timeZoneOffset.inMilliseconds)],
  ).get();
  final days = rows.map((r) => r.read<int>('day')).toSet();
  var cursor = DateTime(now.year, now.month, now.day);
  var streak = 0;
  // 今天没练，从昨天往前数（不把「今天还没开始」算断签）
  if (!days.contains(_epochDay(cursor))) {
    cursor = cursor.subtract(const Duration(days: 1));
  }
  while (days.contains(_epochDay(cursor))) {
    streak++;
    cursor = cursor.subtract(const Duration(days: 1));
  }
  return streak;
}
```

打卡口径：当天至少完成 1 场 `practice_session` 即算；`DISTINCT` 保证一天 5 场只算 1 天；偏移用当前 `DateTime.timeZoneOffset`，中国区无 DST，跨时区误差最多 1 天【假设】。

### 7.6 算法 5：限时模式计时与结算

规则：

1. 60s 从第一题呈现时刻开始（加载与转场不计）。
2. 用单调 `Stopwatch`，墙钟不参与；`Timer.periodic(100ms)` 只刷新 UI 数字。
3. 提交 ≤60000ms 的答案计入，结算晚于 60s 也不追回。
4. 60s 仍未提交的当前题作废：不计 `total`、不写 `answer_record`、不进错题本。
5. 后台切换：`paused` 时停表与 ticker，恢复后由用户点「继续」，避免切回来超时。
6. 提前退出：返回键二次确认，确认后按已答题量写库并进结果页。

```dart
class TimedController {          // 伪代码：省略 finish() 与会话写入
  static const limitMs = 60000;
  final Stopwatch _sw = Stopwatch();
  final List<AnswerResult> _answers = [];
  Timer? _ticker;
  int _elapsedBeforePause = 0;
  bool _finished = false;

  void start() {
    _sw.start();
    _startTicker();
  }

  void _startTicker() {
    _ticker = Timer.periodic(const Duration(milliseconds: 100), (_) {
      if (remainingMs <= 0) finishByTimeout();
    });
  }

  int get elapsedMs => _elapsedBeforePause + _sw.elapsedMilliseconds;
  int get remainingMs => (limitMs - elapsedMs).clamp(0, limitMs);

  bool submit(AnswerResult a) {
    if (_finished || elapsedMs > limitMs) return false;   // 超时提交不计
    _answers.add(a);
    if (elapsedMs >= limitMs) {
      // 压线提交：先给 250ms 反馈，再结算
      Future.delayed(const Duration(milliseconds: 250), finish);
    }
    return true;
  }

  void pause() {
    _elapsedBeforePause += _sw.elapsedMilliseconds;
    _sw.stop();
    _ticker?.cancel();
  }

  void resume() { if (!_finished) { _sw..reset()..start(); _startTicker(); } }

  void finishByTimeout() {
    if (_finished) return;
    _finished = true;
    _ticker?.cancel();
    finish();                                    // total=已答数，未答不计
  }
}
```

结算时 `total = answers.length`，`correct` 与 `avgReactionMs` 从答案算；`levelId` 仍写所选级别，便于看该级正确率。

### 7.7 复杂度与数据量估算

按「50 题/场、每天 1000 题」估算：

| 项目 | 估算 | 依据 |
|---|---|---|
| 单场写入 | 1 事务、51 条 INSERT、≤50 条 upsert，8–20ms | 中端机 WAL，批量写 |
| answer_record 年增 | 365k 行 ≈ 23MB | 1000 题/日 × 365；行 ≈48B + 索引 ≈16B |
| practice_session 年增 | 14.6k 行 ≈ 2MB | 平均 25 题/场 → 40 场/日 |
| wrong_note | ≤58 行 | 29 个自然音 × 2 谱号 |
| 今日统计 | 扫 ≤1000 行，<3ms | 命中 `idx_answer_answered` |
| 近 7 天 | 扫 ≤7000 行，<8ms | 同上，范围扫描 |
| 连续打卡 | 全年 14.6k 行，<10ms | DISTINCT 全扫，年数据量小 |
| 出题 | O(1)，拒绝采样 ≤20 次 | 池 ≤29 |
| 错题加权抽 20 题 | O(20×58)≈1160 次比较，<1ms | 轮盘赌不放回 |
| 结果页首查 | <20ms | 单事务已提交，索引覆盖 |

复杂度结论：出题 O(1)、单题判定 O(1)、错题抽样 O(k·n)（k=10/20，n≤58）、统计 O(天数)。数据保留 2 年（约 50MB）不自动清理；超 200MB 或 50 万行时提示导出 CSV 后清理，单库建议控制在 100MB 内。

### 7.8 算法 6：MIDI 事件 → 答题输入

插件给的是类型化消息，但**不能直接把 `note` 当答案**：要先过「类型、力度、通道、去抖、移调」五道，才得到与题目同一坐标的 `AnswerInput`。这一步写错，表现就是「键盘没反应」或「按一次判两次」。

```dart
AnswerInput? handle(MidiMessage m, {required int transpose, required int nowMs}) {
  if (m is! NoteOnMessage) return null;            // NoteOff / CC / PitchBend 一律忽略
  if (m.velocity == 0) return null;                // velocity 0 即松键，不是新按键
  if (nowMs - _lastAcceptedMs < 300) return null;  // 去抖窗口内只发声不判定
  final accepted = (m.note + 12 * transpose).clamp(0, 127);
  _lastAcceptedMs = nowMs;
  return AnswerInput(midi: accepted, source: InputSource.midi, atMs: nowMs);
}
```

| 步骤 | 规则 | 漏掉的后果 |
| --- | --- | --- |
| 类型过滤 | 只收 `NoteOnMessage` | 收 CC 会把踏板/旋钮判成答案 |
| 力度 | `velocity == 0` → 丢弃（等同 NoteOff） | 大量键盘松键发 NoteOn+vel0，一按判两次 |
| 通道 | 不检查 channel（Omni 1–16） | 代码写死 ch0，而键盘默认 ch1，就全程无响应 |
| 去抖 | 300 ms 窗口内丢弃 | 部分键盘连发 NoteOn，一次按键扣两题 |
| 移调 | `accepted = note + 12 × transpose`，再 `clamp(0,127)` | 不 clamp 会溢出成负数或越界音 |

边界：

- **和弦/多音同时按下**：只取第一条，其余丢弃但照常发声。识谱练习是单音题，和弦属于误触或即兴，不应扣分也不应判对。
- **黑键**：MIDI 没有「白键」概念，用户按黑键时 `accepted` 落在半音体系上，与自然音目标不等 → 判错。与触屏点黑键的行为完全一致，无需特判。
- **计时**：`atMs` 必须与触屏事件用同一个单调 `Stopwatch`，否则两条输入源的 `reactionMs` 不可比，统计页会自相矛盾。
- **多设备**：`MidiCommand` 只会订阅当前连接设备，切换设备时先 `stop()` 旧 adapter 再 `start()` 新 adapter，避免双流叠加导致一次按键两条事件。

### C.6 实际踩到的 5 个坑（按踩坑顺序，均已解决）

1. **Gradle wrapper 的分发包下载不吃 `HTTP_PROXY`。** 现象：`gradle-9.5.0-all.zip.part` 停在 **0 字节**，`flutter build` 挂起 30 分钟无输出。原因：wrapper 用 Java 下载，只认 JVM 系统属性，不认环境变量。解决：用 curl（认 `--proxy`）把分发包直接放进 `%USERPROFILE%\.gradle\wrapper\dists\gradle-9.5.0-all\<hash>\`，并在 `%USERPROFILE%\.gradle\gradle.properties` 写：

   ```properties
   systemProp.http.proxyHost=127.0.0.1
   systemProp.http.proxyPort=10090
   systemProp.https.proxyHost=127.0.0.1
   systemProp.https.proxyPort=10090
   ```

2. **代理会拦 Maven Central（403）。** 现象：`lint-gradle` 的依赖（`groovy:3.0.22`、`kotlin-reflect:2.2.10`、`httpclient:4.5.6`）解析失败，报 `Received status code 403`。实测同一 URL **经代理 403、直连 200**。解决：把这些域名加进 `nonProxyHosts` 直连。

   ```properties
   systemProp.http.nonProxyHosts=localhost|127.0.0.1|*.local|repo.maven.apache.org|repo1.maven.org|plugins.gradle.org|jitpack.io
   ```

3. **插件的 manifest 会覆盖你的 `uses-feature required="false"`。** 现象：我写的是 `false`，但 `aapt2 dump badging` 显示 `android.software.midi` 为必需。根因是 `flutter_midi_command` 自己声明了 `required="true"`，manifest merge 取更严格值。解决：`tools:node="replace"`（见 6.9.2），构建后必须用 `aapt2 dump badging` 复核。

4. **中文路径**：文档放 `E:\dsh\音符识别练习App\` 没问题，**代码工程必须纯英文**（`E:\dsh\notecard`），否则 Gradle/NDK 报路径解析错误。

5. **PowerShell 5.1 的 UTF-8 陷阱**：给 `gradle.properties` 写中文注释会被按 ANSI 解析成乱码，`.ps1` 脚本无 BOM 时同理。→ 所有配置文件注释一律用 ASCII，脚本用 `[System.IO.File]::WriteAllText` + UTF8 显式写。

6. **debug 包与 release 包签名不同，`adb install -r` 会静默失败。**
   现象：`flutter run` 装过 debug 包后，再装 release APK 时 `install -r` 报 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`（或 `VERSION_DOWNGRADE`），因为我用 `Select-Object -Last 1` 吞掉了输出，误以为装上了——结果对着**旧 debug 包**验证了一轮 M2.5，白查一次「移调不持久化」。
   规避：跑验收前先 `adb shell dumpsys package <pkg> | grep versionCode` 确认版本号（release 拆包后是 4001，debug 是 1），装 release 前先 `adb uninstall`。

### C.8 M0 期间新踩的 4 个坑（比 C.6 更硬，全部阻断构建）

这四条的共同背景：**本机 Windows 用户名是中文（`番茄子`）**，而 Gradle/AGP/CMake/ninja 这条链上有三处对非 ASCII 路径处理不当。

1. **中文用户名 → CMake JSON 被写成 GBK 乱码 → Gson 解析失败。**
   现象：`Failed to apply ... :jni:configureCMakeRelWithDebInfo`，报 `MalformedJsonException: Invalid escape sequence at line 3 column 24 path $.buildFiles[0]`。
   根因：`jni` 模块（由官方 `shared_preferences_android` / `path_provider_android` 引入）的 `android_gradle_build_mini.json` 被按系统默认编码写出，`C:\Users\番茄子\...` 变成 `C:\\Users\\鐣寗瀛怽\AppData\\...`，反斜杠转义被破坏。
   解决：给 Gradle daemon 强制 UTF-8 —— `org.gradle.jvmargs=... -Dfile.encoding=UTF-8 -Dsun.jnu.encoding=UTF-8`，同时导出 `JAVA_TOOL_OPTIONS=-Dfile.encoding=UTF-8`，并删掉 `jni-*/.cxx` 缓存。

2. **中文用户名 → ninja 直接报「文件名、目录名或卷标语法不正确」。**
   现象：`ninja: error: FindFirstFileExA(c:/users/番茄子/appdata/local/pub/cache/.../src): ...`
   根因：ninja（CMake 的构建后端）不认非 ASCII 路径，与编码设置无关。
   解决：把 pub 缓存整体迁到 ASCII 路径 —— `Move-Item %LOCALAPPDATA%\Pub\Cache C:\dev\pub-cache`，并设用户环境变量 `PUB_CACHE=C:\dev\pub-cache`。**这是必做项**，否则任何带 CMake 的插件都无法编译。

3. **AGP 9.3.1 + Gradle 9.5.0 的 Kotlin 增量编译缓存损坏。**
   现象：`:shared_preferences_android:compileReleaseKotlin` 报 `Could not close incremental caches ... class-fq-name-to-source.tab`，`flutter clean` 无效。
   解决：`kotlin.incremental=false` + `kotlin.compiler.execution.strategy=in-process`；同时把 AGP 升到 9.5.2、Gradle 升到 9.6.0（AGP 9.5.2 强制要求 Gradle ≥ 9.6.0，wrapper 下载卡住时用 `distributionUrl=file:///C:/dev/dl/gradle-9.6.0-bin.zip` 喂本地包）。
   注意：AGP 9.5.2 下 **不能**开 `android.newDsl=true`，与 `org.jetbrains.kotlin.android` 插件不兼容。

4. **配置文件里写中文注释会被 GBK 读坏。**
   现象：`Set-Content -Encoding ASCII` 把中文注释写成 `?`，并连带把紧随其后的 `kotlin.incremental=false` 吞进注释行，属性静默失效（构建仍报同样的错，白查半天）。
   解决：`gradle.properties`、`.ps1` 一律 ASCII 注释；写文件用 `[System.IO.File]::WriteAllText(path, text, UTF8)`。

### C.9 包体实测与预算冲突（已决策：暂不处理）

> **2026-11-22 决策：包体超预算先不管**，继续推进功能，M4 统一收。

**M4 实测最终包体（arm64 单包）**：27.1 MB → 开 R8 **24.0 MB** → 再加 --obfuscate --split-debug-info **23.0 MB**（v7a 19.8 / x86_64 24.5）。

R8 只压 Java/Kotlin 层，剩下的都是拆不掉的：Flutter engine ≈8 MB、Dart AOT ≈4 MB、SoLoud+sqlite3+jni 原生库、采样 1.2 MB、Bravura 0.87 MB。**20 MB 的原始预算达不到**，建议验收值改成 **arm64 ≤25 MB**；若要真进 20 MB，只能砍 x86_64/v7a 或去掉 SQLite 原生库。

M0 实装产物：arm64 **22.1 MB**、v7a 19.9 MB、x86_64 23.3 MB。

超出 6.6 定的 20 MB 预算，原因是 M0 引入了 `drift + sqlite3 + jni + shared_preferences + path_provider`，`lib/` 下多了 3 个 ABI 的 sqlite3 与 JNI 桥接库。还没算 M1 要加的钢琴采样（约 3.5 MB）与 Bravura 字体（约 0.7 MB）。

三个选项，M1 开始前必须定一个：

| 方案 | 预期包体 | 代价 |
| --- | --- | --- |
| A. 开 R8（`isMinifyEnabled=true` + `isShrinkResources=true`） | 18–19 MB | 首次混淆会让崩溃栈难读，需留 mapping 文件 |
| B. 只发 arm64 单包（不上 Play，侧载为主） | 22 MB 不变 | 老机型装不上，但本项目交付方式本来就是发 APK |
| C. 把预算改到 25 MB | 22 MB | 承认现实，同步改 6.6 / 9.6 / 9.7 的验收值 |

> 建议 B + A 组合：先只出 arm64，再开 R8 压到 18–19 MB，给音频和字体留出空间。
